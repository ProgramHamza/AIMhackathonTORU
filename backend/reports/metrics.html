Pipeline metrics

How well the two blocks we built work: the decision tree (understands the request) and the remarker (marks the passages in the documents). All numbers come from our own evaluation runs. The labels were written by the team, not by doctors, and the data is one synthetic patient, so treat them as a guide, not proof.

What the metrics mean

Right role
Did it understand who is asking (anaesthetist, GP, …)? 100% = every prompt got the right role.
Required items found
Of the facts a doctor must see for this request (we listed them per prompt), how many are on the checklist? Higher is better; a miss means the screen could leave out something important.
Key items ranked high
Are the most important ones (for example blood thinners before surgery) marked critical or high, so they show at the top?
Prompts with everything
Share of prompts where not a single required item was missing. Stricter than the item average.
Irrelevant items shown
Items we listed as useless for that request (for example tumour receptors for an anaesthetist) that still appeared. Lower is better; 0% everywhere.
Checklist length
How many items the screen asks about. Longer lists find more but are noisier for the doctor.
Checks passed (remarker)
For the 15 challenge questions: did the remarker mark a passage from a document that really contains the answer, with the right status? 18 checks, because some questions need two items.
Right status
Found / not documented decided correctly. The two "not documented" answers (kidney function, the follow-up ultrasound) are the hard part.
Source documents found
Of the documents that hold an answer, how many does the remarker point to?
Flags from the right documents
Of the passages it marks, how many come from a document that holds the answer. The rest are related but not the answer; lower means more noise.
Current value right
For drugs: is the dose from the newest letter (April 2016) marked as current, and the older one as history?
Highlights exact
Every marked passage is checked character by character against the document, so the click-through highlight is exact.
API calls per query
Calls to paid or rate-limited cloud services for one question. 0 means it runs entirely from the cached index.

3. Speed

Everything heavy happens once, offline, and is cached. A typical query needs no API call.

Typical prompt, everything understood≈ 10 ms0

Conclusions

  • Use the graph. On unseen prompts it beats the old tree on every metric and shows no irrelevant items.
  • Gemini helps on unusual wording (more required items found on unseen prompts) but costs about 1.5–2 s, so it only runs when words are not understood.
  • Use embeddings in the remarker. They are what lets it say "not documented" with confidence, and they cost no API call at query time.
  • The reranker adds almost nothing here and costs 44 extra calls per patient build; it can stay off.
  • Remarking takes about 10 ms per query, far under the 2-second target. The slowest step is the optional Gemini prompt check.
  • Limits: one synthetic patient, small test sets, labels written by us. A doctor should review the labels and write a blind set.
